What we are building

The names are made up for the series. Meet them once here.

The product

LaunchKit is a marketing assistant. Brands are its customers. A marketer types a request, and LaunchKit answers with the poster's words (the "copy") and the poster's picture with no words drawn into it, both following that brand's rules.

The customers

Harbor makes insulated bottles for people who hike at the weekend and commute in the week. Tidal is the new colourway of its Flask Trail 750 bottle, launching in six weeks, and "the Tidal launch" is the campaign for it. Ember Coffee Co. is the second customer: same software, different voice and rules.

Our part

The harness: the code around the model that reads the brand's rules, makes the model fill a form, checks that form, limits the picture tool, and trusts the request for who the customer is. Then the context talk: which text the harness sent to the model in those runs, in what order, and what it cost.

Words we use

Each word gets defined the first time it is said on the day. This is also the pre-read page in the repo.

Copy
The words on an ad. Poster copy is the headline, the subheadline and the body text. The picture is separate. A copywriter writes copy.
Model
The language model. You send text, it returns text. It knows nothing about Harbor and remembers nothing between calls.
Harness
The code around the model. It decides what the model reads, what it may do, when it stops, and whether its answer is good enough. The model proposes. The harness decides.
Agno
A Python library that gives us the engine: the loop, tool calling, sessions. We keep product rules in our own code.
Workspace
One folder per customer. Harbor has one, Ember has one. Text files in it tell the agent who it is and what the rules are. The idea comes from OpenClaw.
Spec
Our name for the form the model must fill: headline, subheadline, body, image prompt, format. The general idea is called structured output, a harness idea: code can check a form, not prose. Agno does it with output_schema. The fields are ours.
Tool
A function the model may ask the harness to run. The harness runs it and gives the result back to the model.
Step
One turn of the loop: the model answers, or asks for a tool. A run is many steps until the model says it is done, or the harness stops it.
Budget
A cap the harness enforces in code: a number of tool calls, a number of pictures, a size per section of the prompt.
Leash
Our name for the tool hook that counts tool calls. Two numbers, set in settings.py: an image budget of 3 pictures per request and a step cap of 6 tool calls per run. Past the budget a picture call is refused; past the cap the run ends. Built in step 3.
Trace
The list of what happened in one run: files read, model calls, tool calls, refusals, checks, the stop reason. Every check reads it.
Context
Everything the model sees on one turn. We build it in a fixed order with a size per part.
Token
The unit the model bills in. About three quarters of a word. Cost is tokens times a price.

  • The request has four fields: workspace id, user id, conversation id, text. The system sets the first three; the person types only the text. The model never picks the workspace, and the id is checked before any file is opened (step 4).
  • Two model calls per request: one writes the copy as a form the harness checks; a second gets only the image prompt and the picture tool, so no words reach the picture and a bad form never starts one.
  • Three files per request: SOUL.md, AGENTS.md, rules.yaml. The other files in the folder serve the context talk and the chat page, not the request.

Already built, and asked about in the room

  • Memory. Every turn is stored per conversation and the last five go back to the model, so "Make the headline shorter" knows which headline.
  • Poster or reply. The model's form is a Turn: a poster spec for a brief, a plain reply for anything else.
  • Brand and person. The page's two pickers come from each workspace's users.yaml. Each brand-and-person pair has its own conversation; two people never share history.

Value

A rule in the prompt is a request; a rule in code is a guarantee. One repair, then a clear stop, and no paid picture is ever made from bad copy.

The point

The model proposes, the code checks: word limits, banned claims, and copy inside the picture prompt. Errors go back to the model once. If the form is still wrong the run stops with a typed error and no picture is made. The same rule lives twice on purpose: in AGENTS.md as a request to the model, in rules.yaml as a guarantee by the code.

Return one readable error per problem: headline over 6 words, subheadline over 12,
body over 25, any banned claim from rules["banned_claims"] appearing as a whole word in the copy,

If there are errors, record them on the trace with trace.validation(errors, attempt=1),

Answer

# launchkit/harness/spec.py · validate_spec
    errors = []
    for field, limit in WORD_LIMITS.items():
        words = len(getattr(spec, field).split())
        if words > limit:
            errors.append(f"{field} has {words} words, limit is {limit}")
    copy = f"{spec.headline} {spec.subheadline} {spec.body}".lower()
    for claim in rules.get("banned_claims", []):
        if re.search(rf"\b{re.escape(claim.lower())}\b", copy):
            errors.append(f"banned claim: {claim}")
    for field in ("headline", "subheadline"):
        text = getattr(spec, field).lower()
        if text and text in spec.image_prompt.lower():
            errors.append(f"{field} text leaked into image_prompt")
    return errors

# launchkit/harness/run.py · after the copy agent returns
        trace.validation(errors, attempt=1)
        run = agent.run(repair_message(errors), session_id=session, user_id=req.user_id)
        result.runs.append(run)
        trace.model("repair", model_name(model), run.metrics)
        spec = as_turn(run.content).spec or spec
        errors = validate_spec(spec, ws.rules)
        trace.validation(errors, attempt=2)
        if errors:
            raise SpecError(errors)

Value

Spend has a ceiling the model cannot talk its way past. The harness owns the stop, because Agno's own tool_call_limit does not end the loop.

The point

The model gets one tool, the picture, and the harness holds the leash: 3 pictures per request, 6 tool calls per run, both in settings.py. A hook counts every call, refuses a 4th picture and ends the run at a 7th call. Agno's own tool_call_limit does not end the loop, so the harness owns the stop. The picture call is a second model call that sees only the image prompt, never the headline.

The picture is drawn from the description alone. A poster built from the brand's own product photo is request R3, Session 2.

# launchkit/harness/limits.py · make_leash
    calls = {"total": 0, "generate_image": 0}

    def leash(function_name: str, function_call, arguments: dict):
        calls["total"] += 1
        if calls["total"] > limits.step_cap:
            trace.stop(f"step cap of {limits.step_cap} tool calls reached, run ended")
            raise StopAgentRun(f"Step cap of {limits.step_cap} tool calls reached")
        if function_name == "generate_image":
            calls["generate_image"] += 1
            if calls["generate_image"] > limits.image_budget:
                reason = f"image budget of {limits.image_budget} spent"
                trace.refused(function_name, reason)
                return {"status": "refused", "reason": reason}
        result = function_call(**arguments)
        trace.tool(function_name, arguments, result)
        return result

Value

One customer can never reach another's files. Who is asking comes from the sign-in, and the id is checked before any file is opened.

The point

Who is asking comes from the request, never from the text. The workspace id is a field the sign-in sets; the page's Brand picker stands in for that sign-in. # launchkit/harness/request.py · resolve_workspace_id
    workspace_id = request.workspace_id
    if not WORKSPACE_ID.fullmatch(workspace_id) or not (settings.workspaces_dir / workspace_id).is_dir():
        raise UnknownWorkspace(workspace_id)
    return workspace_id

Block T · after the build

Talk · Context engineering: what the model was sent, in what order, at what cost

Branch

session-01-harness-step4the finished harness; two terminal runs and explain

The point

The prompt is built from four sections in a fixed order, each with a size budget: rules, task, facts, history. Everything the model knows is in there; nothing else exists for it. A budget stops the bill, and it also cuts lines, so the right fact has to be found and loaded, not pasted whole. That is where retrieval, the next segment, starts.

Run

Small file. The product sheet fits, and the copy is right.

uv run launchkit run harbor "Poster for the Tidal bottle. Mention it's dishwasher-safe." --facts workspaces/harbor/facts.md
  prompt    rules: 174 tokens · task: 170 tokens · facts: 86 tokens
  body      Keeps drinks cold 24h, hot 12h. Dishwasher-safe body, leak-proof lid, plastic-free.

Big file. The brand book is about 1,970 tokens against a facts budget of 1,500. The product facts sit at the end of the book, so the cut removes them, and the model turns a true fact down.

uv run launchkit run harbor "Poster for the Tidal bottle. Mention it's dishwasher-safe." --facts workspaces/harbor/brand-book.md
  prompt    rules: 174 tokens · task: 170 tokens · facts: 1444 tokens (cut to fit)
  reply     The product sheet doesn't mention dishwasher safety. I can't include that claim.  (no poster this turn)

The fact was in the file. The budget cut it. Not a model mistake, a context mistake.

Then uv run launchkit explain, the prompt of that last run, section by section:

run bd00dabf · harbor · OpenAI:gpt-4.1-mini · copy phase

  rules              174      1500
  task               170       400

Four rules to leave the room with: a fixed order; a budget per section; the stable part first, so the provider can cache it (OpenAI caches a prefix from 1,024 tokens, and ours is shorter, so the cached column stays 0 here); detail fetched when a turn needs it, not pasted up front. The Pencil story: moving the catalogue and brand block behind a lookup cut Scribble's instructions from 44 KB to about 21 KB, and a fixed test caught a lost "confirm before deleting" rule.
