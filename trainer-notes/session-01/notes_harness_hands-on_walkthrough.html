What we are building

The names are made up for the series. Meet them once here.

The product

LaunchKit is a marketing assistant. Brands are its customers. A marketer types a request, and LaunchKit answers with the poster's words (the "copy") and the poster's picture, both following that brand's rules.

The customers

Harbor makes insulated bottles for people who hike at the weekend and commute in the week. Tidal is the new colourway of its Flask Trail 750 bottle, launching in six weeks, and "the Tidal launch" is the campaign for it. Ember Coffee Co. is the second customer: same software, different voice and rules.

Our part

The harness: the code around the model that reads the brand's rules, makes the model fill a form, checks that form, limits the picture tool, and trusts the request for who the customer is. Then a look at what the model saw in those runs, and what it cost.

Words we use

Each word gets defined the first time it is said on the day. This is also the pre-read page in the repo.

Copy
The words on an ad. Poster copy is the headline, the subheadline and the body text. The picture is separate. A copywriter writes copy.
Model
The language model. You send text, it returns text. It knows nothing about Harbor and remembers nothing between calls.
Harness
The code around the model. It decides what the model reads, what it may do, when it stops, and whether its answer is good enough. The model proposes. The harness decides.
Agno
A Python library that gives us the engine: the loop, tool calling, sessions. We keep product rules in our own code.
Workspace
One folder per customer. Harbor has one, Ember has one. Text files in it tell the agent who it is and what the rules are. The idea comes from OpenClaw.
Spec
Our name for the form the model must fill: headline, subheadline, body, image prompt, format. The general idea is called structured output, a harness idea: code can check a form, not prose. Agno does it with output_schema. The fields are ours.
Tool
A function the model may ask the harness to run. The harness runs it and gives the result back to the model.
Step
One turn of the loop: the model answers, or asks for a tool. A run is many steps until the model says it is done, or the harness stops it.
Budget
A cap the harness enforces. A step cap. An image budget. A size per section of the prompt.
Trace
The list of what happened in one run: files read, model calls, tool calls, refusals, checks, the stop reason. Every check reads it.
Context
Everything the model sees on one turn. We build it in a fixed order with a size per part.
Token
The unit the model bills in. About three quarters of a word. Cost is tokens times a price.
Fake model
A stand-in for the real model that returns a scripted answer. Free, instant, and it lets a check prove the harness without a key.

Skeleton rules

  • Every slot has a dumb default. The app runs before step 1. Each step makes it smarter. Nobody is stuck with a crash.
  • Trace is the eyes. Every box writes to it. The terminal prints it. The page streams it. Every check reads it.
  • Real model for live runs, fakes for checks. run and the chat page use the real model whenever a key exists. check N always uses fakes, so it is repeatable, instant and free, and can force bad cases. With no key, live runs use the Good fake so nothing crashes. Pictures follow the same pattern.

Shipped parts, in one line each

  • resolve_model: reads LAUNCHKIT_MODEL. Missing key: a clear error naming the var. Never a silent swap.
  • ContextBuilder: sections in fixed order, rules → task → facts → history. A token budget per section. render() trims. report() lists tokens used per section.
  • Session state: Agno's SQLite db, add_history_to_context=True, last 3 runs. Turn 2 remembers turn 1.
  • Fakes: subclass Agno's Model the way Agno's own benchmarks do. Four scripted models.
  • Images: real adapter calls OpenAI images. Fake adapter draws a PNG with the brand colour and the prompt text.
  • UI: one page, server-sent events for the live trace. An "Onboard a brand" panel: upload a PDF, get the four files drafted.
  • A turn is a poster or a reply. The copy form is a Turn: the model says whether the message asks for a poster or deserves a plain reply. "hi" gets a greeting and no picture. Added 15 Oct at Ajay's request.
  • Brand and person, two lists. The chat page has a brand list and a person list from each workspace's users.yaml (Maya and Sam at Harbor, Jonas at Ember). Each brand-and-person pair has its own stored conversation it comes back to. The harness keys sessions by brand, person and conversation, so two people never share history. No id boxes. Added 15 Oct.
  • Onboarding: the PDF is stored under assets/, its text goes to the model with a BrandProfile form, code writes the files. The marketer owns them after that. Added 15 Oct at Ajay's request.

def load_workspace(workspace_id: str, trace: Trace) -> Workspace:
    root = settings.workspaces_dir / workspace_id
    soul = read_text(root / "SOUL.md", trace)
    agents = read_text(root / "AGENTS.md", trace)
    rules = yaml.safe_load(read_text(root / "rules.yaml", trace))
    return Workspace(id=workspace_id, root=root, soul=soul, agents=agents, rules=rules)

def build_copy_agent(ws: Workspace, ctx: ContextBuilder) -> Agent:
    ctx.set("rules", f"{ws.soul}\n\n{ws.agents}")
    ctx.set("task", SPEC_TASK)
    return Agent(
        model=resolve_model(),
        system_message=ctx.render(),
        output_schema=PosterSpec,
        db=settings.db,
        add_history_to_context=True,
        num_history_runs=3,
    )

WORD_LIMITS = {"headline": 6, "subheadline": 12, "body": 25}

def validate_spec(spec: PosterSpec, rules: dict) -> list[str]:
    errors = []
    for field, limit in WORD_LIMITS.items():
        words = len(getattr(spec, field).split())
        if words > limit:
            errors.append(f"{field} has {words} words, limit is {limit}")
    copy = f"{spec.headline} {spec.subheadline} {spec.body}".lower()
    for claim in rules.get("banned_claims", []):
        if claim.lower() in copy:
            errors.append(f"banned claim: {claim}")
    for field in ("headline", "subheadline"):
        if getattr(spec, field).lower() in spec.image_prompt.lower():
            errors.append(f"{field} text leaked into image_prompt")
    return errors

# run.py
spec = run.content
errors = validate_spec(spec, ws.rules)
if errors:
    trace.validation(errors, attempt=1)
    run = agent.run(repair_message(errors), session_id=req.session_id, user_id=req.user_id)
    spec, errors = run.content, validate_spec(run.content, ws.rules)
if errors:
    trace.validation(errors, attempt=2)
    raise SpecError(errors)

def generate_image(image_prompt: str) -> dict:
    """Make the poster picture from a description. The picture contains no words."""
    path = settings.images.generate(image_prompt, settings.current_colours())
    return {"file": str(path)}

def make_leash(limits: Limits, trace: Trace):
    calls = {"total": 0, "generate_image": 0}

    def leash(function_name: str, function_call, arguments: dict):
        calls["total"] += 1
        if calls["total"] > limits.step_cap:
            trace.stop(f"step cap {limits.step_cap} reached")
            raise StopAgentRun(f"Step cap of {limits.step_cap} reached")
        if function_name == "generate_image":
            calls["generate_image"] += 1
            if calls["generate_image"] > limits.image_budget:
                trace.refused(function_name, "image budget spent")
                return {"status": "refused", "reason": f"image budget of {limits.image_budget} spent"}
        result = function_call(**arguments)
        trace.tool(function_name, arguments, result)
        return result
    return leash

picture_agent = Agent(
    model=resolve_model(),
    system_message=PICTURE_TASK,
    tools=[generate_image],
    tool_hooks=[make_leash(settings.limits, trace)],
)
run = picture_agent.run(spec.image_prompt)

Agno 3.1 names used: hook signature (function_name, function_call, arguments) from the hooks page; StopAgentRun from agno.exceptions, documented for tool functions and pre/post hooks. Raising it inside a wrapping hook is the one thing to prove first. verify at build

WORKSPACE_ID = re.compile(r"^[a-z0-9-]{1,32}$")

def resolve_workspace_id(request: Request) -> str:
    wid = request.workspace_id
    if not WORKSPACE_ID.match(wid) or not (settings.workspaces_dir / wid).is_dir():
        raise UnknownWorkspace(wid)
    return wid

Small on purpose. The point is where the id comes from, and that the harness never parses text for it.

Arc

  1. Small file. Run uv run launchkit explain on the last Harbor run from the room. Four sections in order: rules, task, facts (empty), history. Tokens per section, total input tokens, cost in cents. "This is everything the model saw. Nothing else exists for it."
  2. Big file. Paste brand-book.md, 40 pages, into the facts section (one flag: --facts brand-book.md). Run again. Cost jumps. The budget trims the file. The line "lid is hand-wash only" is cut. Ask "mention it's dishwasher-safe". The copy says dishwasher-safe. "The fact existed. The model never saw it."
  3. Four rules. Fixed order. A budget per section. Stable part first, so the provider caches it: show cached tokens on the second run of the same workspace. Fetch detail just in time, as a tool call, not up front. The Pencil story: moving the catalogue and brand block behind a lookup cut Scribble's instructions from 44 KB to about 21 KB, and a fixed test caught a lost "confirm before deleting" rule.
  4. The open problem. "Budgets stop the bill. They do not choose the right lines. The facts section needs something that finds the few lines that matter, when they matter. That is retrieval." Hand over.
