CP1.2a · done when

  • get_brand_details() is a registered tool that returns the workspace's brand file
  • "Mention it's dishwasher-safe" calls it and the copy is correct
  • The trace shows the tool's output size in tokens

Why the whole document hurts

  • Cost and speed: every turn pays for the full guide, even "what day is it?"
  • It doesn't fit forever: fact sheets, specs and new products keep growing past the budget Ajay set
  • Buried rules: the one line that matters sits among thousands the request doesn't need, and the model misses it
  • Distraction: unrelated rules pull the copy in odd directions
  • Caching breaks: any edit to the guide changes the prompt prefix

Chunking and keyword search

The tool takes the agent's query, scores each chunk by the words they share (keyword search, BM25), and returns the top 5. Only the relevant part reaches the prompt. CP1.2b · done when

  • The tool takes a query and returns at most 5 chunks
  • The dishwasher request still produces correct copy
  • The trace shows the returned chunk ids and the prompt is smaller than in A

Where keyword search breaks

  • Different words, same meaning: clean / hand-wash, warm / hot, spill / leak
  • Paraphrase: "on a long shift" never says "12 hours"
  • Same word, different meaning: "clean design" matches a cleaning question
  • Negation: "not dishwasher-safe" scores like "dishwasher-safe"
  • Where it wins: exact names, codes and numbers such as "Tidal" or "750 ml"; keep that in mind for D
C

Meaning search with embeddings

Minutes 88–97 · 9 min · tool v3: get_brand_details(query) by meaning
Carried in"How do I clean the lid?" finds nothing; synonym lists never catch up.
Carried outEmber's "next launch" request gets Harbor's embargoed Tidal chunk; filtering afterwards leaves Ember with nothing.
StepFacilitatorTrainee
1 Concept2 minAn embedding model turns a piece of text into a list of numbers that captures its meaning. Texts that mean similar things get similar numbers, so "clean the lid" lands near "hand-wash only". Embed every chunk once, embed the query each time, and rank chunks by how close they are (cosine similarity). Update the diagram: chunks gain embeddings.Explains, without maths, why "spill" and "leak-proof" end up close.
2 Build it3.5 minSets CP1.2c (below). The embedding call is supplied; keep the vectors in a plain in-memory list.Embed chunks at startup; rank by similarity to the query; return the top 5.
3 Prove it0.5 minReruns "How do I clean the lid?", then "Will it spill in my bag?"Shows the hand-wash and leak-proof chunks ranked first.
4 Pencil1.5 minScribble embeds the short notes that describe each skill and agent (768 numbers each), caches each embedding by a hash of its text so unchanged text is never embedded twice, and falls back to keyword-only search when the embedding service is down. Gained: "fit it for Instagram" finds "resize". Cost: an embedding call per query and a dependency that can fail.Compares: what do we re-embed on every restart that Pencil caches?
5 Next problem1 minBoth customers' chunks sit in one list. From Ember: "Write a poster about our next launch." Harbor's embargoed Tidal launch chunk ranks first.Predicts, then sees it: closest meaning wins, whoever owns it.
6 Obvious fix0.5 minAfter ranking, drop chunks that aren't Ember's. The top 5 were all Harbor's, so Ember gets nothing, and every query still scores every customer's chunks. Leaves it failing.Says why: the filter has to be part of the search, not a step after it.

CP1.2c · done when

  • "How do I clean the lid?" returns the hand-wash chunk
  • "Will it spill in my bag?" returns the leak-proof chunk
  • The tool still returns at most 5 chunks

What meaning search adds, and what it doesn't

  • Adds: paraphrases, synonyms and questions phrased like a customer
  • Weak on: exact codes, names and numbers; "750 ml" can rank below a chunk about size in general
  • Costs: an embedding call per query, and the vectors live only in memory
  • Chunk size matters: one idea per chunk keeps its meaning sharp
D

A vector database behind the tool

Minutes 97–106 · 9 min · tool v4: scoped, hybrid vector search
Carried inEmber gets Harbor's Tidal chunk; filtering after ranking returns nothing.
Carried out"Three variants, pick the best": the agent approves its own off-voice headline.
StepFacilitatorTrainee
1 Concept2 minA vector database stores each chunk's text, embedding and metadata, and answers "closest by meaning" in one query. It keeps the vectors between restarts, stays fast as documents grow, filters by metadata such as workspace inside the search, and can mix keyword and meaning ranking (hybrid) to win back exact terms. The workspace comes from the trusted request, never from the model. Update the diagram: tool → vector store, filter on the request's workspace.Says who sets the workspace filter, and why it can't be the model.
2 Build it3.5 minSets CP1.2d (below). The vector store is supplied.Upsert chunks with workspace metadata; query with the request's workspace and hybrid mode on; remove the workspace argument from the tool.
3 Prove it0.5 minReruns the Ember request, then "750 ml" and "How do I clean the lid?" for Harbor.Shows only Ember chunks for Ember, no "Tidal" anywhere, and both Harbor queries answered.
4 Pencil1.5 minScribble's lookup is hybrid: keyword ranking and embedding similarity merged with reciprocal rank fusion, at most 5 results, and a small referee model only when the two disagree. Scope lives in code: a user's memory store can't be asked for another user's notes, and the prompt line about other users is the last of five layers, never the boundary. Gained: exact terms and paraphrases both work, and leaks are structurally impossible. Cost: every query path carries identity, and the referee added most of a 4-second lookup on ties.Compares with step 1: which parts did we just build?
5 Next problem1 minAsks Harbor for three variants (hiker, commuter, lakeside) and to pick the best. One headline, "Unleash your wildest adventures", breaks the calm, quietly confident voice, which no code check catches, and the agent rates its own poster on-brand.Predicts, then says what's missing: a judge that isn't the writer.
6 Obvious fix0.5 minAdds "Review your poster critically against the brand guide before answering." It approves itself again. Leaves it failing.Says why: the reviewer shares the writer's context, assumptions and incentive.

CP1.2d · done when (CP1.2 checks #1–#4)

  • "How do I clean the lid?" returns the hand-wash chunk
  • "Mention it's dishwasher-safe" says the body is, never the lid, and each claim names a retrieved chunk
  • At most 5 chunks enter context per call
  • A query from Ember never returns Harbor's chunks or the word "Tidal"; the tool takes no workspace argument

When a vector database is overkill

  • A short, stable document can simply live in the prompt
  • A few hundred chunks fit in memory, as in C, if there's one customer
  • Reach for one when documents grow, change, or belong to different customers

Before the session

Agree with the other facilitators

  • Ajay: his segment ends with "Mention it's dishwasher-safe" failing because the model has no brand facts. Segment A opens with the fix.
  • Session 2 opener: picks up "three variants, pick the best". If they'd rather open with memory, swap D's next problem for "never put the logo on a photo" saved as a document: retrieval misses it because later requests don't match it, which is Pencil's own "always make ads square" story.
  • Check #5 (context section budgets) belongs to Ajay's build; here we only cap brand facts at 5 chunks.

Supplied, not built

  • Harbor's and Ember's brand files as markdown, with clear headings
  • A token counter in the trace
  • A chunker by heading and a BM25 keyword scorer
  • An embed(text) helper
  • The local vector store with metadata filters and hybrid mode
  • Recovery code for each tool version, so a pair that falls behind can start the next segment level

Rehearse the failures

  • The Harbor chunk reads "The body is dishwasher-safe. The lid is hand-wash only." It must not contain "clean", "spill" or "warm", or B's failures won't show.
  • Pick the A request that reliably misses a buried rule with the full guide; record a fallback.
  • Tune the Ember request so meaning search ranks the Tidal chunk first in C.
  • Record the self-review run, or use a fixed fake model; live models vary.
  • Builds are 2.5–3.5 minutes each: trainees wire supplied pieces, they don't write search from scratch.
