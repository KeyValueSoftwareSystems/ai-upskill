Why the whole document hurts

  • Cost and speed: every turn pays for the full guide, even "what day is it?"
  • It doesn't fit forever: fact sheets, specs and new products keep growing past the budget Ajay set
  • Buried rules: the one line that matters sits among thousands the request doesn't need, and the model misses it
  • Distraction: unrelated rules pull the copy in odd directions
  • Caching breaks: any edit to the guide changes the prompt prefix

Where keyword search breaks

  • Different words, same meaning: warm / hot, spill / leak-proof
  • No stemming: "dent" does not match "dents"
  • Same word, wrong place: "warm" matches the tone rule "Brief and warm"
  • Negation: "not dishwasher-safe" scores like "dishwasher-safe"
  • Where it wins: exact names, codes and numbers such as "Tidal" or "750 ml"

Meaning search with embeddings, in a vector database

Minutes 88–97 · 9 min · tool v3: get_brand_details(query) by meaning · branch session-01-rag-step3
Carried in"How long does my coffee stay warm?" returns tone rules; "What if it gets a dent?" finds nothing; synonym lists never catch up.
Carried outHarbor's "Is this product suitable for night shift?" gets five of Ember's Night Shift chunks; filtering afterwards leaves Harbor with nothing.
StepFacilitatorTrainee
1 Concept2 minAn embedding model turns a piece of text into a list of numbers (a vector) that captures its meaning. Texts that mean similar things get similar numbers, so "stay warm" lands near "hot for 4 hours". A vector database (LanceDB, a folder on disk) stores one row per chunk: its text, its vector and which brand it belongs to. Indexing is document processing: chunks are embedded once, when a brand file is uploaded, never on a turn. A lookup embeds only the question and asks the database for the 5 closest rows (cosine similarity). Update the diagram: upload → chunks → vectors → store; tool → store.Explains, without maths, why "spill" and "leak-proof" end up close.
2 Build it3.5 minSets CP1.2c (below). The embedding call (bge-small-en-v1.5, local, no key) and the store are supplied.Index a brand when its file is uploaded; the tool embeds the question and queries the store for the top 5.
3 Prove it0.5 minUploads both brand books into their own workspaces (this indexes them), then asks Harbor "How long does my coffee stay warm?"Shows the answer "4 hours" and the chunk lines ranked by cosine score.
4 Pencil1.5 minScribble embeds the short notes that describe each skill and agent (768 numbers each), caches each embedding by a hash of its text so unchanged text is never embedded twice, and falls back to keyword-only search when the embedding service is down. Gained: "fit it for Instagram" finds "resize". Cost: an embedding call per query and a dependency that can fail.Compares: which part of Pencil's design did we just copy? (Our store also skips chunks whose text hash is unchanged.)

What meaning search adds, and what it doesn't

  • Adds: paraphrases, synonyms and questions phrased like a customer
  • Weak on: exact codes, names and numbers
  • Costs: an embedding call per query; the vectors are stored once and survive a restart
  • Chunk size matters: one idea per chunk keeps its meaning sharp. An uploaded PDF has no headings, so it is chunked one line at a time
  • Not yet: any notion of whose chunk it is

Keep each brand to its own chunks

CP1.2d · done when (CP1.2 checks #1–#4)

  • "How do I clean the lid?" returns the hand-wash chunk

When a vector database is overkill

  • A short, stable document can simply live in the prompt
  • A few hundred chunks for one customer fit in memory
  • Reach for one, with filters, when documents grow, change, or belong to different customers
